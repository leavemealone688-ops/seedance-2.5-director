# 画幅、分辨率、参赛规格与预算

## 9:16 vs 16:9

| | 9:16 竖屏 | 16:9 横屏 |
|---|---|---|
| 用途 | 竖屏短剧、抖音、Shorts、Reels | 参赛片、预告片、长视频平台 |
| 构图 | 人物占画面比例大；单人中近景为主；双人上下错落或前后景 | 可横向调度；双人左右对称、过肩正反打；大全景建立空间 |
| 写法 | `Vertical 9:16` 写在第一句；主体居中，避开上下 UI 区 | `16:9 cinematic widescreen`；可写 2.35:1 宽银幕质感 |
| 风险 | 横向动作出画；多人挤 | 竖屏平台被裁 |

- 定妆照和衔接帧尽量和成片同画幅。
- **竖转横 / 横转竖不要靠裁**：需要两种画幅就分别生成；或生成时留安全区（主体居中，上下或左右留空），再裁。
- 参赛片规格（时长、分辨率、帧率、字幕要求、是否允许 AI 标识）先读比赛章程，写进项目计划第一行；本包不替任何比赛下结论。

## 分辨率

- 团队常用 720P / 720p 出正片；先低分辨率（480p 样片 / 草稿）试构图和表演，满意再出高清，可省预算。
- 1080p / 4K：即梦、Higgsfield 已公开上线 4K 档【官方，2026-11】，价格团队未实测。
- 帧率：团队在 Vigloo 提示词里写过 24fps；实际输出帧率以平台为准，用 `ffprobe` 核对。

## 预算

提交前算清，并得到负责人同意：

```bash
python3 scripts/cost_calc.py --platform xiaoyunque --clips 8 --retry 0.5
python3 scripts/cost_calc.py --platform vigloo --seconds 20 --clips 4 --retry 0.5
```

- 费率表在 `scripts/cost_calc.py` 顶部，每条带来源和日期；未实测的组合脚本会拒绝计算。
- 对白镜头经验上常要 1-2 版 → 默认留 50% 重跑余量。
- 估算 ≠ 实扣，以确认页 / Generate 按钮为准；提交后记录实际扣费。
- 省钱：草稿档试错；一次只跑一条；能剪辑解决的问题不重跑；CLI 提交可能不享受网页折扣（LibTV 实测）。
