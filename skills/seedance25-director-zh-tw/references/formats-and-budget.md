# 畫幅、解析度、參賽規格與預算

## 9:16 vs 16:9

| | 9:16 豎屏 | 16:9 橫屏 |
|---|---|---|
| 用途 | 豎屏短劇、抖音、Shorts、Reels | 參賽片、預告片、長影片平台 |
| 構圖 | 人物佔畫面比例大；單人中近景為主；雙人上下錯落或前後景 | 可橫向排程；雙人左右對稱、過肩正反打；大全景建立空間 |
| 寫法 | `Vertical 9:16` 寫在第一句；主體居中，避開上下 UI 區 | `16:9 cinematic widescreen`；可寫 2.35:1 寬銀幕質感 |
| 風險 | 橫向動作出畫；多人擠 | 豎屏平台被裁 |

- 定妝照和銜接幀儘量和成片同畫幅。
- **豎轉橫 / 橫轉豎不要靠裁**：需要兩種畫幅就分別生成；或生成時留安全區（主體居中，上下或左右留空），再裁。
- 參賽片規格（時長、解析度、幀率、字幕要求、是否允許 AI 標識）先讀比賽章程，寫進專案計劃第一行；本包不替任何比賽下結論。

## 解析度

- 團隊常用 720P / 720p 出正片；先低解析度（480p 樣片 / 草稿）試構圖和表演，滿意再出高畫質，可省預算。
- 1080p / 4K：即梦、Higgsfield 已公開上線 4K 檔【官方，2026-11】，價格團隊未實測。
- 幀率：團隊在 Vigloo 提示詞裡寫過 24fps；實際輸出幀率以平台為準，用 `ffprobe` 核對。

## 預算

提交前算清，並得到負責人同意：

```bash
python3 scripts/cost_calc.py --platform xiaoyunque --clips 8 --retry 0.5
python3 scripts/cost_calc.py --platform vigloo --seconds 20 --clips 4 --retry 0.5
```

- 費率表在 `scripts/cost_calc.py` 頂部，每條帶來源和日期；未實測的組合腳本會拒絕計算。
- 對白鏡頭經驗上常要 1-2 版 → 預設留 50% 重跑餘量。
- 估算 ≠ 實扣，以確認頁 / Generate 按鈕為準；提交後記錄實際扣費。
- 省錢：草稿檔試錯；一次只跑一條；能剪輯解決的問題不重跑；CLI 提交可能不享受網頁折扣（LibTV 實測）。
